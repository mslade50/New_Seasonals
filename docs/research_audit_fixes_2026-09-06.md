## Contract notes

- Raw replay is a research price-return simulation, not reconciled broker P&L. Existing adjusted series for relative strategy engines and trend research stay unchanged. No historic scoreboard or journal was regraded in this task. Scheduled raw-price availability still requires a normal provider connection; this task made none.
- JSONL mirror synchronization still assumes the existing local-primary writer model. Local locks do not provide distributed concurrency across independent machines writing the same R2 mirror. Corrupt evidence is preserved and requires explicit reviewed recovery; it is never silently skipped, truncated or reset.
- A completed v2 underwrite answering DEEPEN records `research_control_updated_at` (the exact request timestamp) and `completed_at`. The report copies these completion receipts into `research_control_state.completed_requests`, which the run manifest preserves. A screen/report alone does not count as completed diligence. Historical legacy records without explicit completion evidence leave the request pending.
- EV reconciliation is `price × diluted_shares × share_unit_multiplier / money_unit_multiplier + net_debt + sum(ev_adjustments.amount)`, with 0.5% relative / 0.01 absolute rounding tolerance. Multipliers default to 1. Additional EV components must name their source IDs. Price/valuation currencies must already match; this code does not guess or fetch FX. `quote_source_ids` can separate fresh market quotes from older filing/share-count evidence; when omitted, `source_ids` is the quote-source contract.
- Ambiguous EP receipts require provider/manual reconciliation. This fix deliberately provides no automatic inference that an uncertain email was not delivered. Receipt locks apply to the shared local filesystem, not separate machines with separate receipt directories.
- Shared Access currently supports explicit individual emails. A team group or other selector needs a reviewed validation implementation before that deployment check will accept it. No user's approved address list or live policy was changed.
- R2 conditional-put behavior was checked against the [official Workers API reference](https://developers.cloudflare.com/r2/api/workers/workers-api-reference/#conditional-operations): rejected conditions return null. Tests reproduce that response rather than treating every write as successful.
